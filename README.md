# 📚 Лиза — Telegram-бот по Genshin Impact и «Осквернённому Граалю»

Лиза Минчи, библиотекарь Ордо Фавониус, отвечает на вопросы по Genshin Impact и по настольной
игре «Осквернённый Грааль» (Tainted Grail: «Падение Авалона», «Короли краха»)
(RAG: векторный поиск в ChromaDB + Claude API).

---

## 🏗️ Архитектура (docker-compose)

```
            ┌──────────────┐
            │  ipcheck     │  common/ipcheck.py — IP через прокси в ALLOWED_SUBNET? (exit 0/1)
            └──────┬───────┘
                   │ только при успехе
            ┌──────▼───────┐
Telegram ◄──┤  bot         │  bot/ — Лиза, ищет контекст и спрашивает Claude
            └──────┬───────┘
                   │ HTTP
            ┌──────▼───────┐
            │  chroma      │  chromadb/chroma, данные в ./chroma_db
            └──────▲───────┘

            ┌──────┴───────┐
Fandom,  ──►│  updater     │  updater/updater.py — при старте и раз в сутки: вики, Project Amber,
Amber,      └──────┬───────┘  paimon.moe
```

## 🔑 Ключи и настройки

Настройки — в `.env` (шаблон: `.env.example`), персональная часть промпта (кто есть кто
в чате) — в `data/prompt_private.txt` (шаблон: `data/prompt_private.example.txt`), пометка для администратора
(снимает с Лизы правило конфиденциальности для `ADMIN_USERNAMES`) — в `data/prompt_admin.txt`
(шаблон: `data/prompt_admin.example.txt`). `.env`, `prompt_private.txt` и `prompt_admin.txt` в git не попадают.

- `TG_BOT_TOKEN` и данные Telethon — в `.env`.
- `ANTHROPIC_API_KEY` — **из `~/.bashrc`** (переменная окружения хоста), запросы идут
  в `api.anthropic.com` через HTTP-прокси `ANTHROPIC_PROXY` (пусто — напрямую). Через прокси идёт только
  Claude API; Telegram, вики и проверка IP — напрямую.
  Compose не запустит бота, если переменная не задана.
- `CLAUDE_MODEL` — опционально, по умолчанию `claude-sonnet-4-5`.

## 🛡️ Ограничения доступа

**IP.** Claude API можно использовать только если внешний IP, с которым запросы выходят
через прокси `ANTHROPIC_PROXY`, принадлежит `ALLOWED_SUBNET` (обязательная переменная в `.env`; не задана — проверка не проходит).
IP определяется через ipify/ifconfig.me/icanhazip/ipinfo, Claude для проверки не используется.
Если хоть один сервис видит IP вне подсети или IP не определился — проверка не пройдена.
- сервис `ipcheck` запускается первым; не прошёл → падает, и compose не запускает бота;
- бот перепроверяет IP каждые `IP_CHECK_INTERVAL` секунд (300). При неверном IP он **не падает**:
  Claude не вызывается, а Лиза отвечает случайной фразой из `AKASHA_DOWN` в `bot/texts.py`
  («Прости дорогой, но Акаша сейчас не доступен» и др.). Пока Акаша недоступен, проверка
  повторяется каждые `IP_RECHECK_INTERVAL` секунд (60), после восстановления IP бот снова отвечает;
- `parsers/chat.py` не запустится вне подсети.

**Прокси перед каждым запросом.** Перед каждым обращением к Claude бот проверяет, открывается ли
TCP-соединение с прокси `ANTHROPIC_PROXY` (таймаут `PROXY_CHECK_TIMEOUT`, 3 с). Если нет — Claude
не вызывается, Лиза отвечает фразой из `AKASHA_DOWN`. То же — если сам запрос к Claude не смог
подключиться.

**Фоновая проверка связи.** Каждые `NET_CHECK_INTERVAL` секунд (30) бот проверяет Telegram и прокси
и пишет в лог, когда связь пропала и когда восстановилась. Важно: Telegram и прокси ходят через
один VPN (`vpn0`). Если упал VPN целиком, сообщения до Лизы не доходят и ответить даже
«Акаша недоступен» она не может. Такие сообщения она получит и обработает, когда связь вернётся.
Чтобы проверить именно `AKASHA_DOWN`, блокируйте только прокси:
`sudo iptables -I DOCKER-USER -d 10.10.10.102 -j DROP` (вернуть — то же с `-D`).

**Чаты.** Лиза отвечает только в чатах из `ALLOWED_CHATS` (через запятую, по умолчанию `TG_CHAT`),
а в личке — участникам этих чатов: Лиза проверяет через Telegram (`getChatMember`), состоит ли
пользователь хотя бы в одном из них (ответ кэшируется: «да» — на 10 мин, «нет» — на 1 мин).
Из чужих групп бот сразу выходит.

Автозапуск отключён (`restart: "no"`), после перезагрузки сервера контейнеры
нужно поднять вручную:

```bash
source ~/.bashrc

docker compose logs -f bot updater
docker compose down                 # остановить всё
```

## 🔄 Обновление базы

Сервис `updater` обновляет базу **сразу при старте** и затем раз в сутки в `UPDATE_TIME`
(UTC, по умолчанию `01:00` = 04:00 МСК). Источники обновляются независимо: ошибка одного
не мешает остальным, неудачная синхронизация повторяется через час.

| Источник | Что даёт | Как обновляется |
|----------|----------|-----------------|
| **Вики** (genshin-impact.fandom.com/ru) | статьи, включая данные инфобоксов (редкость, элемент, регион, дата выхода, баннер…) | по `recentchanges` только изменённые статьи; полностью — если прошлой синхронизации не было, она старше 30 дней или изменилась обработка статей (`WIKI_SCHEMA`) |
| **Project Amber** (gi.yatta.moe) | данные из файлов игры на русском: персонажи (профиль, таланты, созвездия), оружие (пассивки R1/R5), наборы артефактов; новые персонажи — в день выхода версии | целиком, но в базу записываются только изменившиеся документы |
| **paimon.moe** (данные из github.com/MadeBaruna/paimon-moe) | молитвы и события: актуальные — в служебную коллекцию `bot_state` (для бота), история молитв по персонажам/оружию и по версиям — в базу | целиком, в базу — только изменения |

| **«Осквернённый Грааль»** — отдельная коллекция `tainted_grail` | правила из PDF в `./data/tainted_grail/` (страницы-карты на английском отсеиваются), «Путеводитель по миру „Осквернённого Грааля“» Crowd Games (VK), лор вселенной — категория Lore вики *Tainted Grail: Conquest* (англ., тот же мир), база лора из `./data/tainted_grail/grail/` (режется по разделам, спойлеры помечаются). Энкаунтеры не загружаются | целиком, в базу — только изменения |

Бот каждый раз прикладывает к вопросу блок «Сейчас в игре»: дату, текущие и следующие
молитвы и события из базы (кэш 5 минут).

**Служебная коллекция `bot_state`** (`STATE_COLLECTION`) в той же ChromaDB хранит состояние
вместо файлов на диске (модуль `common/state.py`):

| Запись | Кто пишет | Что |
|--------|-----------|-----|
| `updater:<коллекция>` | updater | время и итоги последней синхронизации каждого источника, версия обработки вики |
| `banners:current` | updater | актуальные молитвы и события paimon.moe для блока «Сейчас в игре» |
| `dialog:<chat_id>:<user_id>` | бот | история диалога с Лизой (последние `MAX_HISTORY` пар вопрос-ответ и тема) — переживает перезапуск |
| `pray:<user_id>` | бот | счётчики гарантии и статистика `/pray`, молитвы за сутки (`day`, `today`) и бонусные (`extra`) |
| `tasks:<user_id>` | бот | на какие задания записан (`tasks`) и когда выполнял (`done`: задание → сутки) |
| `tasks_meta:<задание>` | бот | за какие сутки уже отправлено напоминание |
| `menu:<chat_id>` | бот | id закреплённого меню (чтобы убрать прежнее) |
| `sent:<chat_id>` | бот | id последних сообщений Лизы для `/delete` |

Состояние updater лежит в той же базе, что и данные: при восстановлении `chroma_db` из бэкапа
оно откатывается вместе с ней. Если коллекция вики пуста, вики загружается полностью.

Ручной запуск:

```bash
docker compose run --rm updater python -m updater.updater --once   # инкрементально
docker compose run --rm updater python -m updater.updater --full   # то же, вики — полностью
docker compose run --rm updater python -m updater.updater --once --only amber paimon   # выбранные источники
```

## 🔎 Выбор базы

Если в вопросе есть маркеры «Осквернённого Грааля» (Грааль, Авалон, менгир, искаженье,
«Короли краха», имена героев…), бот ищет в коллекции `tainted_grail`, иначе — в базе Genshin
(с блоком «Сейчас в игре»). Уточняющие вопросы без ключевых слов остаются в теме предыдущего
вопроса диалога; `/reset` сбрасывает и тему.

В чатах из `TG_PRIORITY_CHATS` любой вопрос считается вопросом
по «Осквернённому Граалю»; на Genshin бот переключается только по явным маркерам (Genshin, Тейват,
Паймон, примогемы, молитвы…). Лиза не переспрашивает, о какой игре речь.

## 💬 Меню и кнопки

Команды заменены inline-кнопками. Меню присылают `/start` и `/menu` (в списке команд Telegram
остаётся только `/menu`). Кнопки работают при любом режиме приватности бота; кто нажал — Лиза
знает по Telegram id. Ответы, которые касаются только нажавшего (лимит молитв, сброс диалога,
отказ), приходят всплывающим окном — в чат не пишутся.

**В группе** — только молитвы. Меню: «🙏 Помолиться» (в `PRAY_CHAT_ID`) и кнопка-ссылка
«💌 Задания и рейтинг — у Лизы в личке». Меню, вызванное администратором (`ADMIN_USERNAMES`),
Лиза закрепляет, а прежнее удаляет (боту нужны права закреплять и удалять сообщения).

**В личке** — для участников разрешённых чатов (см. «Чаты»): задания, рейтинг, сброс диалога
и вопросы Лизе. Ссылки из группы (`/start tasks`, `/start stats`) сразу открывают нужный раздел.

| Кнопка | Где | Описание |
|--------|-----|----------|
| 🙏 Помолиться | группа `PRAY_CHAT_ID` | Молитва на текущем баннере персонажа (из paimon.moe). Шансы как в игре: 5★ 0,6% с мягкой гарантией с 74-й и жёсткой на 90-й, 4★ каждые 10, 50/50 со стандартными 5★. Лимит — `PRAY_DAILY_LIMIT` молитв в сутки (по умолчанию 1), сброс в 00:00 UTC+3; сверх лимита — бонусные молитвы за задания Лизы, они не сгорают в полночь. Счётчики у каждого свои, хранятся в ChromaDB (коллекция `bot_state`). Пользователям из `PRAY_BONUS_USERS` бонус: 10% на Джинн, даже если её нет в баннере. Результат — в чат, под ним снова «Помолиться». Работает без Claude |
| 📋 Задания Лизы | личка | Список заданий с записью/отпиской. Сейчас задание одно — «Ежедневная отметка у Паймон»: в 19:00 (UTC+3) Лиза пишет каждому записавшемуся в личку (если бот был выключен — сразу после запуска, в тот же вечер; вышедшим из чатов и заблокировавшим бота — не пишет) с кнопкой «Я отметился(-ась)». Награда (+1 бонусная молитва) — нажавшему, раз в сутки; после нажатия кнопка исчезает, кнопки прошлых суток не работают |
| 📜 Рейтинг молитв | личка | Рейтинг чата: больше 5★ — выше, при равенстве — кому они дешевле дались; плюс своё место и сколько до гарантии |
| 🧹 Забыть наш разговор | личка | Очистить историю диалога с Лизой (и в базе) |
| (упоминание / ответ боту) | группа | Вопрос Лизе; в личке — любое сообщение |

Старые команды скрыты из списка, но работают: `/pray` (в группе молитв), `/reset`, `/delete` (удалить последнее
сообщение Лизы в чате, только для `ADMIN_USERNAMES`, не старше 48 ч); `/tasks` в группе отвечает ссылкой в личку;
`/praystats` в группе от администратора (`ADMIN_USERNAMES`) публикует рейтинг для всего чата молитв
(сама команда удаляется), остальным — ссылка в личку.

При старте бот сам меняет своё имя в Telegram на «Лиза» (`set_my_name`).

## ⚠️ Замечания

- Docker-сеть проекта с MTU 1350: часть трафика хоста идёт через VPN (`vpn0`, MTU 1354),
  с MTU 1500 TLS-соединения из контейнеров (например, к GitHub) зависали.

- `data/session_parser.session` хранит авторизацию Telethon — не делись им.
- `data/knowledge_base.json` содержит переписку — храни его приватно. История диалогов с Лизой
  (`dialog:*` в `bot_state`, т.е. в `./chroma_db`) — тоже.
